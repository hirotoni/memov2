# PLAN

## Goal

CLI から到達可能な path-traversal 残存リスクを塞ぐ。`memos open [path]`
（および `memos rename` が共有する `resolveToMemosDir`）に、ユーザー提供パスが
`..` などで `MemosDir()` の外へ解決した場合に **reject** する検証を追加する。
これは直前コミット(`f0bf4c1`)が実装したカテゴリツリー path-traversal 対策の、
計画文書で「同種・スコープ外の残存リスク」と明記されていた続き。

## Current Findings

- `internal/service/memo/path.go:13` `resolveToMemosDir(memosDir, path)` は
  現状 3 ケースを扱う:
  1. 絶対パス → そのまま返す（**MemosDir 外でも通す**）
  2. CWD 経由で解決した絶対パスが MemosDir 配下 → その絶対パスを返す
  3. それ以外 → `filepath.Join(memosDir, path)`（**`..` を含むと MemosDir 外へ脱出**）
- 呼び出し元は 2 箇所、いずれも既に `error` を返す:
  - `internal/service/memo/open.go:4` `Open(path)` — `cmd/memos/open.go` が
    `memos open [path]`(`cobra.ExactArgs(1)`)で **生パス引数**をそのまま渡す。
    つまり `memov2 memos open ../../../../etc/passwd` で MemosDir 外の任意ファイルを
    エディタで開ける。CLI から直接到達可能な実害経路。
  - `internal/service/memo/rename.go:16` `Rename(path, newTitle)` — 現状は
    `RenameInteractive`(ピッカー)経由のみだが、同じ関数を共有するため一緒に保護する。
- 既存の検証ヘルパは `domain.ValidateCategoryTree`(直前コミットで追加)。
  今回はパス境界の検証なので、`resolveToMemosDir` 自体で解決後の絶対パスを
  MemosDir 配下かどうか prefix チェックするのが自然。
- `internal/service/memo/path_test.go` は存在しない（新規追加する）。

## Decisions

- **reject 方針**（直前計画と一貫）: 解決後パスが MemosDir 配下に収まらない場合は
  黙ってサニタイズせず、`common.ErrorTypeValidation` エラーで失敗させる。
- `resolveToMemosDir` のシグネチャを `(string, error)` に変更する。ケース1(絶対パス)も
  含め、**最終的に返す絶対パスが必ず MemosDir 配下であること**を単一箇所で保証する。
  これにより「絶対パスは無検証で通す」現状の穴も同時に塞ぐ。
- 正常系は維持する:
  - list コマンド出力の相対パス `"category/file.md"` は引き続き解決・許可。
  - CWD が MemosDir 配下のときの相対パス解決も引き続き許可。
  - `MemosDir()` 自身（ルートちょうど）は許可、その外は拒否。境界は
    `filepath.Clean(memosDir)` と、その配下（`memosDir + separator` prefix）で判定。

## Scope

In scope:
- `internal/service/memo/path.go` — `resolveToMemosDir` を `(string, error)` に変更し、
  解決後の絶対パスが `MemosDir()` 配下であることを検証。外れたら
  `common.New(common.ErrorTypeValidation, ...)` を返す。3 ケース全てで最終検証を通す。
- `internal/service/memo/open.go` — 新シグネチャに合わせ、エラーを呼び出し元へ伝播。
- `internal/service/memo/rename.go` — 新シグネチャに合わせ、エラーを伝播。
- `internal/service/memo/path_test.go`（新規）— テーブルテストで正常系/拒否系を網羅。

Out of scope（残存リスクとして記録、今回修正しない）:
- backlog の他項目（todo 過去ファイル削除、検索タイトル直下、config、リファクタ）。
- `browse.go` などの UI 自由入力経路（カテゴリ検証は直前コミットで repository 境界にて
  カバー済み。今回のパス境界検証とは別レイヤ）。
- symlink 経由の脱出（`filepath.EvalSymlinks` までは今回踏み込まない。prefix チェックで
  `..` テキスト脱出を塞ぐことを主目的とする）。

## Steps

1. `internal/service/memo/path.go`:
   - `resolveToMemosDir(memosDir, path string) (string, error)` に変更。
   - 各ケースで候補となる絶対パス `resolved` を求める:
     - 絶対パス → `resolved = filepath.Clean(path)`
     - 相対パス → `abs, _ := filepath.Abs(path)`; `cleanAbs` が MemosDir 配下なら
       `resolved = cleanAbs`、そうでなければ `resolved = filepath.Clean(filepath.Join(memosDir, path))`
   - 共通の末尾検証: `cleanRoot := filepath.Clean(memosDir)`。
     `resolved == cleanRoot` または `strings.HasPrefix(resolved, cleanRoot + separator)` を満たさなければ
     `common.New(common.ErrorTypeValidation, fmt.Sprintf("path escapes memos directory: %s", path))` を返す。
   - 満たせば `(resolved, nil)` を返す。
2. `internal/service/memo/open.go`: `path, err := resolveToMemosDir(...)`; err を伝播。
3. `internal/service/memo/rename.go`: `path, err = resolveToMemosDir(...)`; err を伝播
   （既存の err 変数/戻り値に合わせる）。
4. `internal/service/memo/path_test.go`（新規, テーブルテスト）:
   - 正常: `"category/file.md"`（相対・list 出力形式）→ `memosDir/category/file.md`。
   - 正常: MemosDir 配下の絶対パス → そのまま。
   - 正常: MemosDir ルートちょうど → 許可。
   - 拒否: `"../../etc/passwd"` → ErrorTypeValidation。
   - 拒否: MemosDir 外の絶対パス（例 `/etc/passwd`）→ ErrorTypeValidation。
   - 拒否: `"category/../../.."` のような正規化後に脱出するケース → ErrorTypeValidation。
   - 境界: `memosDir` と紛らわしい兄弟ディレクトリ（例 `memosDir` が `/a/memos` のとき
     `/a/memos-evil`）が prefix 誤判定で通らないこと。

## Risks

- `open`/`rename` の既存呼び出し側が `resolveToMemosDir` の string 単独戻り値に
  依存 → シグネチャ変更で両呼び出し元の同時修正が必須（漏れるとビルド不可なので
  コンパイル時に検出可能、リスク低）。
- symlink 経由の脱出は今回のテキスト prefix チェックでは防げない（スコープ外・残存リスク）。
- Windows のパス区切り差異: `string(filepath.Separator)` を用いて OS 非依存に保つ。
